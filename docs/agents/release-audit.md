# AM4 release quality gate

AM4は情報の正確さと、迷わず読める・押せる体験を同じ品質で扱う。変更の規模に応じて、必要な監査だけを積み上げる。

## Every change

- 変更差分を確認し、関係するテスト、構文確認、`git diff --check` を実行する。
- 既存のネタバレ保護、同一生成元API、秘密情報の非露出を壊していないか確認する。
- 反映前に、変更内容・確認結果・未確認事項を短く記録する。

## Visible UI, navigation, or content-card changes

- 1人の独立レビュー担当が、差分を対象に情報の階層、現在地表示、文言、余白、タップ領域、モバイル表示、キーボード操作を監査する。
- 実ブラウザを利用できるときは、ホーム、記事、試合詳細のうち影響する画面を実際に確認する。ブラウザ確認ができないときは、その理由を残し、プレビューURLを共有する。
- カードを主要導線にする場合、カード全体で移動でき、保存・結果表示などの補助操作は独立して使えることを確認する。

## Production release

- 本番反映前にテスト、差分監査、影響画面の確認を終える。
- 反映後に本番URLと必要な公開APIを確認する。
- P1/P2の未解決指摘がある場合は、本番反映しない。例外はユーザーがリスクを理解したうえで明示的に判断した場合だけ。

## Audit depth and cost

- 小さな文言・データ変更は「Every change」だけを基本とし、低コストで回す。
- UI・導線・デザイン変更は追加で1回の独立レビューを行う。
- ホームの構成、デザインシステム、試合一覧、記事・試合詳細の大幅変更、または公開前の節目だけ、主要画面を横断する全体監査を行う。

常に複数の監査エージェントを走らせるのではなく、変更の種類に合わせて深さを上げる。これでトークンを浪費せず、今回のような「現在地が違う」「どこを押せばよいか分からない」といった違和感を見逃しにくくする。
